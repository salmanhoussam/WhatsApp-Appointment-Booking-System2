# تحقيق D10-x — بنيةُ الكاتالوج: هل `CatalogService` و`CatalogItem` خطأ؟

**التاريخ:** ٢٠٢٦-٠٩-١٦ · **الطالب:** سلمان — *«موضوع catalog من زمان مش عاجبني، حاسس فيه شي غلط»*
**النوع:** تحقيقٌ بقراءةٍ فقط. صفرُ كتابة · صفرُ تعديلِ كود (عدا تصحيحِ docstring مُعتمَدٍ مسبقاً).
**الأسئلة:** Q1 جدوى الدمج · Q2 معنى `moduleKey` · Q3 التسميات · Q4 صفُّ `mr-h`.

## Confirmed Findings

### Q1 — 🔴 الدمجُ خطأٌ معماريّ. والفرضيّةُ التي بنينا عليها السؤالَ **منقلبة**

`CatalogItem` و`CatalogService` متطابقان في ١٧ حقلاً، **لكنّ رسمَهما العلائقيَّ متعاكس**:

```
CatalogItem   →  storeCartItems · storeOrderItems · galleryImages        جانبُ الطلب/الشراء
                 و**صفرُ علاقةٍ بالحجز** — لا FK من Reservation إليه إطلاقاً

CatalogService ←  Reservation.serviceId   52/52 صفّاً حيّاً
               ←  BarberService           41 صفّاً
               ←  BookingService           0 صفّاً (القناةُ قائمةٌ لـsmar)
```

**والانفصالُ كان قراراً موثَّقاً، لا سهواً.** تعليقُ الschema عند السطر ٥٣٠:

> *«Split out of CatalogItem in Phase 3.7C (2026-08-08) — CatalogItem already had zero schema
> relation to Reservation and three real relations to order-side concepts; **this was being bolted
> on via `metadata.requires_booking` only**.»*

**والمستندُ المُحال إليه موجود** (Reference Validation ✅):
`.claudedocs/work/staff-service-relationship-investigation/2026-08-08/summary.md` ·
`.claudedocs/evolution/staff-capability.md`

```
⇒ ما شعرتَ أنّه «غلط» ليس الانفصال — بل **مخلَّفُ ما قبله**:
  صفٌّ واحدٌ ما زال يعبّر عن «قابلٌ للحجز» بـmetadata.requires_booking، وهي الطريقةُ
  التي وُجد CatalogService كي تُلغيها.
⇒ والدمجُ اليوم يعني **إعادةَ إنشاء العطب الذي أُصلح**، ونقلَ ثلاثةِ FK حيّةٍ (٩٣ صفّاً)
  إلى جدولٍ علاقتُه بالحجز معدومة.
```

### Q2 — 🟡 `moduleKey` **ليس بوّابة، وليس كاذباً**. وتصحيحٌ لصياغتي السابقة

قلتُ في تقريرٍ سابق إنّ *«moduleKey يكذب على أهمّ جدول»*. **الصياغةُ كانت أقوى ممّا يحتمل الدليل.**

`moduleKey` **مُقسِّمُ أقسامٍ (partition discriminator)** داخل جدولَي الكاتالوج المشتركَين،
ويُستعمل بكثافةٍ واتّساق:

```
admin/store.py        module_key="store"  على ٨ مواضع:  إنشاءٌ · قراءةٌ · تحديثٌ · حذفٌ للفئة والعنصر
admin/restaurant.py   module_key="restaurant"  بالمثل
admin/catalog.py      يقبله معاملاً
والمسارات العامّة      تُرشِّح به
```

⇒ فوظيفتُه أن تَرى مساراتُ المتجر صفوفَ المتجر وحدها — **وهي تؤدّيها بلا استثناءٍ واحد.**

**والتصادمُ الحقيقيُّ أضيقُ وأدقُّ ممّا وصفتُ:** القيمةُ `"catalog"` تُسمّي **شيئين لا علاقةَ بينهما**:

```
moduleKey = "catalog"          قسمُ الكاتالوج العامّ داخل الجداول     ← وفيه تعيش كلُّ الخدمات (36/36)
serviceKey = "catalog"          مفتاحُ قدرةٍ في client_services        ← ومعطَّلٌ على التينانتات الثلاثة
```

فخدماتُ المحلّ تعيش في قسمٍ اسمُه `catalog`، **وتُحرَس ببوّابة `reservations`** — وهذا متّسقٌ
تماماً حين يُفهم أنّ الاسمَين لا يقصدان الشيءَ نفسه. **والعناصرُ متّسقةٌ في الحالتين**
(`store`→`store` · `restaurant`→`restaurant`).

### Q3 — 🔴 ثلاثةُ معانٍ لكلمة «service»، والمشروعُ يعرف المشكلةَ بالاسم

```
(١) منتجُ المنصّة        platform_services · client_services · require_service()
(٢) ما يبيعه المحلُّ لزبونه  CatalogService
(٣) طبقةُ الكود           app/services/*.py
```

وتعليقُ الschema نفسُه يسمّيها: *«same naming-collision class this project has hit before
("four meanings of service")»*.

**🟢 وسببُ الاسم المضاعَف `CatalogService` لم يعد قائماً.** التعليق يقول إنّه سُمِّي كذلك
*«because a completely unrelated `Service` model already exists»* — **وذاك الموديل حُذف**
في `2d464d7` (٢٠٢٦-٠٩-٠٧) مع `service_service.py` و`booking_service_service.py`.

```
⇒ التصادمُ الذي فرض الاسمَ المضاعَف: زال.
⇒ فإعادةُ التسمية صارت **ممكنةً** — وكلفتُها migration + ~٤٥ ملفّاً تذكره.
```

### Q4 — 🔴 صفُّ `mr-h` عطبُ منتجٍ حقيقيّ، لا فضولٌ تاريخيّ

```
mr-h · CatalogService (يُحجَز):   شعر · شعر ودقن · كرياتين · دقن · شعر ودقن وتمشيط · حنة أو صبغة
mr-h · CatalogItem   (لا يُحجَز): «تمشيط أو تسريح»  5 USD  {duration_min:20, requires_booking:true}

ونفسُ الخدمة على التينانتَين الآخرَين، في الجدول الصحيح:
   rk               CatalogService  «تمشيط أو تسريح»  5 USD · 20د
   barberlab-test   CatalogService  «تمشيط أو تسريح»  5 USD · 20د
```

```
⇒ «تمشيط أو تسريح» خدمةٌ يقدّمها mr-h **ولا يستطيع أيُّ زبونٍ حجزَها** — بنيويّاً،
  لأنّ Reservation لا يملك FK إلى CatalogItem.
⇒ وحجوزاتُ mr-h الإحدى عشرة كلُّها تشير إلى CatalogService حصراً.
⇒ فالصفُّ ليس بياناً تاريخيّاً خاملاً: هو **دخلٌ ضائعٌ صامت** على تينانتٍ حيّ.
```
