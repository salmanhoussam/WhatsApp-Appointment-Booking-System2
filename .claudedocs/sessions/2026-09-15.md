### 2 · Key Technical Concepts

- FastAPI + Prisma (prisma-client-py) + Supabase Postgres (Frankfurt,
  `aws-0-eu-central-1.pooler.supabase.com`) + React/Vite on Railway; `gunicorn -w 2` (two workers)
- WhatsApp Cloud API: 24-hour customer-service window; templates are the ONLY type sendable outside
  it; `new_reservation_alert` is the only approved template
- **Meta's interactive list holds 10 rows TOTAL** across all sections
- `require_service()` reads **`client_services`** (clientId + serviceKey + isActive) — the runtime
  source of truth; `platform_services` has **zero** runtime reads
- `is_authorized(user, permission, *legacy_roles)` — the single authorization predicate shared by
  dashboard and WhatsApp
- `VERTICAL_REGISTRY` in `app/core/verticals.py` — platform-owned, read-only, "No runtime write path
  exists or should ever exist here"
- Reservation pipeline: `Validate → Resolve Resource → Resolve Barber → Resolve Service → Working
  Hours → Conflict Check → Resolve Customer → Create → Post Actions`
- `VALID_STATUSES` = pending|confirmed|arrived|cancelled|no_show; `TRANSITIONS`:
  `pending → [confirmed, cancelled]`, `confirmed → [arrived, cancelled, no_show]` —
  **`pending→arrived` is illegal**
- `datetime.now().replace(tzinfo=timezone.utc)` — the deliberate convention (naive-local labeled
  UTC), NOT `datetime.now(timezone.utc)`
- AI → JSON → Pydantic (`model_validate_json`) with `extra="forbid"`
- `whatsapp_sessions.stateData` (30-min TTL, refreshed on every `upsert`) is the only session store
- `wamid UNIQUE` as insert-as-claim idempotency for inbound
