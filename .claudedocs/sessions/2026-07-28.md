## 🔧 Technical Decisions Made

- **`Tenant → One Module` is a wrong domain concept, not an under-scoped one** — the backend's
  `client_services` table was always an unbounded set; the frontend's single derived `moduleKey`
  was a simplification later outgrown by the first tenant (`hr`) with more than one active
  catalog-bearing capability.
- **Retire the concept entirely, don't build a smarter single-value replacement** — explicit
  instruction from Salman, honored throughout: no new `deriveCapabilityBadge()`-style function.
- **The Admin topbar module badge is removed, not redesigned** — Capability Discovery now happens
  through the real Tabs/rendered content; a synthetic module label was a Duplicate Representation.
- **Migration order: prove → migrate consumers → verify → delete last** — same discipline as the
  Editing Engine's own history; nothing was deleted until every real consumer was independently
  verified, and a Search Verification gate ran before the final deletion.
