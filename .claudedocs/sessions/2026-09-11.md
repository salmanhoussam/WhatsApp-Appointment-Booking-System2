### 2. Key Technical Concepts

- Multi-tenant SaaS: FastAPI + Prisma (prisma-client-py) + Supabase Postgres (Frankfurt
  `eu-central-1`) + React/Vite on Railway
- 4-layer architecture (Routes → Services → Repositories → DB); every query filtered by `clientId`
- WhatsApp Cloud API: 24-hour customer-service window, `wamid`, `statuses[]` callbacks, error codes
  `131047` (re-engagement/window), `131026` (undeliverable), `190` (token)
- Meta accepts asynchronously: HTTP 200 + `wamid` then async `statuses[]` failure — a send response
  is never delivery
- `_fire_and_forget` + "never raises" notification contract
- Phone rule: storage WITH country code, entry WITHOUT; `app/core/phone.normalize_for_storage` vs
  `user_repo.normalize_local_phone`
- Tenant resolution: JWT slug → `X-Tenant-Slug` → `?client_slug=` → subdomain; inbound WhatsApp
  resolves via `Client.phone` matched against Meta's `display_phone_number`
- ADR-0001 Hard Block (`status`), ADR-0002 Soft Block (`lifecycle_state`) — both fail OPEN on NULL
- Playwright MCP browser verification protocol
- Railway CLI (authenticated) vs Railway MCP (needs interactive OAuth)
