## 🐛 Bugs Fixed

| Bug | File | Root Cause | Fix Applied |
|-----|------|------------|-------------|
| **Live 500 on every reservation with metadata** | `reservation_service.py` | Prisma's generated types for this client reject a bare `None`/`dict` for an optional `Json?` field — needs the key omitted or wrapped in `Json(...)` | Wrap `metadata` in `Json(...)`, only include the key when a real value exists |
| **No working-hours enforcement existed** | `reservation_service.py` | Never built — confirmed via full codebase grep | New validation reading `Client.config.working_hours`, real 409 on violation |
| **`scheduled_at` field doesn't exist in the backend response** | `ReservationsTab.jsx` (3 places) | Table silently fell back to the booking's *creation* time instead of its actual appointment time — invisible in a flat table, would be immediately wrong in a calendar | Changed to the real field, `reserved_at` |
| **UTC vs local-timezone display mismatch** | `ReservationsWeekCalendar.jsx` | Component used `getHours()`/`getDate()` (local) while the backend validates in UTC — an 11:00 UTC booking rendered at ~14:00 (EEST, UTC+3). Caught by the *first real screenshot* taken during verification | Made every date/time helper in the component UTC-consistent |
| **Real out-of-order API response race** | `ReservationsTab.jsx` | Switching List→Calendar fired a new fetch before a slower, older one resolved; the stale empty result landed second and silently overwrote correct data | Added a request-sequence guard (`requestSeqRef`) in `load()`; stale responses are now dropped |
| **`seed_catalog.py`'s `KNOWN_TENANTS` whitelist** (worked around, not fixed) | `scripts/seed_catalog.py` | `argparse choices` doesn't include `store-pilot-test-20260727` | Seeded the pilot's 5 items directly via the admin API instead of this script — noted as a real limitation of the script for future synthetic pilots, not fixed in the script itself |
