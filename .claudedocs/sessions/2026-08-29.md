- `user_repo.py`: new `normalize_local_phone()` (strip non-digits, strip leading `961`) — used by
  `find_user_by_phone()` on the login input, and by `registration_service.py` when persisting a
  new tenant's `User.phone` at registration.
- Verified against real values: `+9613300778899` → `3300778899`, `96176985477` → `76985477`,
  `76985477` → `76985477` (already local, unchanged) — all consistent.

**Corrected backfill SQL** (matches the code's own normalization exactly, given to Salman in place
of the earlier un-normalized version):
```sql
UPDATE users u
SET phone = CASE
    WHEN length(regexp_replace(c.phone, '[^0-9]', '', 'g')) > 3
         AND regexp_replace(c.phone, '[^0-9]', '', 'g') LIKE '961%'
    THEN substring(regexp_replace(c.phone, '[^0-9]', '', 'g') from 4)
    ELSE regexp_replace(c.phone, '[^0-9]', '', 'g')
END
FROM clients c
WHERE u.client_id = c.id
  AND u.role = 'TENANT_ADMIN'
  AND u.phone IS NULL;
```
