rather than kept as a standalone document (`fb8581e`, `7f291da`).

## Part 6 — Sprint 2: Media Capability (`ReplaceMedia`)

Salman's explicit direction for the next Capability, and why: *"ليس لأنها الأسهل، بل لأنها ستختبر
شيئًا جديدًا بالكامل... هل الـ Editing Engine يعمم على نوع Operation مختلف مثل ReplaceMedia؟"* —

Built `content_sections_repo.py` (promoting Part 5's private helper into a genuinely shared

Rule's "≥2 independent cases" bar met a second time), `media_service.py`, `app/api/v1/admin/
media.py`, `schemas/media.js`, wrapped `HeroSection.jsx`'s background layer in
`<EditableRegion capability="media">`, and generalized `GenericAdminDashboard.jsx`'s handler to
branch on `field.type` (text → prompt, image → a real hidden file input).

**Verification was a real, multi-round debugging session, not a single clean pass**:
- First CDP run found the media `EditableRegion` "NOT FOUND" — root cause was insufficient wait
  time before checking the iframe's content (fixed by polling for `[data-capability]` before
  proceeding).
- `DOM.setFileInputFiles` initially failed with an invalid `nodeId: 0` — fixed by calling
  `DOM.getDocument` before `DOM.requestNode`, a real CDP protocol sequencing gap in the test
  script.
- The click then landed on a nav link instead of the hero background — the test's coordinate math
  (`iframe.getBoundingClientRect().left + 40`) wrongly assumed the hero sat at the iframe's own
  top-left corner. Fixed by measuring the `EditableRegion`'s actual rendered child and dispatching
  a direct synthetic `MouseEvent` on it rather than fighting CDP's page-level coordinate mapping.
- With the click landing correctly, a real upload fired but the `PATCH /media/hero-image` request
  returned a genuine **422** — the actual application bug this sprint's verification caught: schema
  entries conflated `dataField` (the `section.data` key) with the PATCH body's own key. Content's
  two fields happened to share the same name for both, hiding the gap; Media's route
  (`image_url` vs. `dataField`'s `bg_image_url`) didn't. Fixed by adding an explicit `apiField` to
  every schema entry, decoupling the two concerns for good.

Final run succeeded end-to-end, confirmed three independent ways: backend log (`POST /upload/` 200
→ `PATCH /media/hero-image` 200), a direct read of `GET /public/{slug}/config` showing the real
Supabase URL written into the DB, and a before/after screenshot of the live preview switching from
the gradient placeholder to the real uploaded photo. Evidence, the schema-mismatch bug, and an
honest Media Capability maturity note (one proven field, not the full Contract) written to
`.claudedocs/work/tenant-os-sprint2/2026-07-22/SPRINT2_EVIDENCE.md`; `TENANT_OS_PLAN.md` §19/§20/§22
updated to match; committed (`c4fdb01`).

## Part 7 — Admin/Public Contract: a New Platform-Wide Rule

Reviewing Sprint 2, Salman identified a real architectural distinction that existed in the code but
had never been written down: the Editing Engine's write path (`Dashboard → Admin API → DB`) and the
live preview's read path (`DB → Public API → iframe`) are two genuinely different Contracts, not
incidental plumbing — and this split is exactly what makes the live preview a real end-to-end
proof rather than a mock. He gave the target framing directly: *"Admin Contract: mutable,
authenticated, operation-based. Public Contract: read-only, optimized for rendering, consumed by
all tenant interfaces,"* and asked it be written as a standing architectural rule, not a new
Capability.

Verified real before writing anything (not assumed): `content.py`/`media.py` confirmed under
`app/api/v1/admin/`; `DynamicPage.jsx` — the component both the live preview and every real
visitor render — confirmed to import only `publicApi`, never `adminApi`. Added
`.claude/rules/backend/architecture.md` §10 (the canonical statement, mirroring §9's existing
style), a corresponding subsection in `TENANT_OS_PLAN.md` §14 with both the current-state and
future Draft/Publish diagrams Salman gave, and a standing `bo-hussein.md` Team Leadership
responsibility to check this boundary before any new Capability work from Sprint 3 onward — a
violation classifies under §19's existing Broken Architecture finding type, deliberately not a new
category (`1a0f81d`).

Salman's follow-up praised three specific things about how this was done: verifying real
implementation before documenting intent, reusing the existing Finding taxonomy instead of adding
a new one, and elevating the check to a standing `bo-hussein` responsibility rather than a
one-time note. He also flagged a further concept — Capability Contract as the true parent, with
Admin/Public as two *projections* of it rather than independent contracts — and explicitly asked
that it **not** be documented yet, deferred until a 2nd/3rd real Capability (Site Configuration or
Catalog) repeats the same shape, per the Abstraction Rule. Both the documentation methodology and
this deferred concept were saved to memory
(`feedback_architecture_rule_documentation.md`, `project_tenant_os_capability_projection.md`) so
future sessions inherit them without re-deriving.

## 🔧 Technical Decisions Made

- **Capability → Operation → Schema → Renderer**, not a better click-to-edit UI — Salman's core
  architectural correction that shaped the entire day.
- **No Dispatcher, no Schema Registry, no Operation-execution service** built ahead of proof —
  deferred twice now (Sprint 1's review, Sprint 2's Architecture Review), each time re-confirmed
  as the right call rather than assumed.
- **`content_sections_repo.py` promoted to a genuinely shared repository** only once Media needed
  the identical shape Content's own extraction had already proven — the Abstraction Rule applied a
  second time, not a first guess.
- **`apiField` added to every schema entry**, decoupling "key inside `section.data`" from "key the
  route's Pydantic model expects" — a real, general fix, not a one-off patch for Media alone.
- **Admin/Public Contract elevated to a platform rule** (`rules/backend/architecture.md` §10),
  verified against real code first; a boundary violation classifies under the existing Broken
  Architecture finding type rather than a new taxonomy entry.
- **"Capability Contract as parent, Admin/Public as projections" deliberately not documented yet**
  — held in memory as a deferred concept with an explicit trigger condition (a 2nd/3rd Capability
  repeating the shape), not a time-based one.
