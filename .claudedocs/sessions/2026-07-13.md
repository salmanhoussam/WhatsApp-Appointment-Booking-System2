## 🔧 Technical Decisions Made

- **Reverted the 3D cube-rotation Caracas Special reel back to flat crossfade** — user's direct feedback: "i didnt like [the dice], make it just scroll down with cool button and text appear." Kept all 7 real videos; only the transition mechanic changed.
- **Higgsfield CLI cannot do real generation on this trial plan** — confirmed via direct testing that `generate create` and `product-photoshoot create` both fail with `only_mcp_usage_on_trial_is_available`, even called directly (not just via the higher-level skill wrapper). Only `--enhance-only` previews and cost/account checks work via CLI. All real generation this session went through the MCP `generate_image`/`generate_video`/`upscale_image` tools instead.
- **anas built inside SalmanSaaS, not as a standalone Next.js project** — user's initial prompt described a generic Next.js+Tailwind+separate-Supabase build; reconciled with the existing platform (shared Prisma catalog tables, tenant registry, same Supabase bucket) since footlab/sneakers-beirut already prove this pattern works for store-type tenants.
- **No fake content anywhere for anas** — no invented product entries, no fabricated reviews, no made-up WhatsApp number/address/hours. Everywhere real data is missing, the UI shows an honest "coming soon" / "قريباً" state instead. The owner will add real products via the `/anas/admin` dashboard (reusing `GenericAdminDashboard.jsx` — the shared admin, not a bespoke one).
- **Categories decided from the real video, not the user's original guess** — video showed ceramics only (plates/bowls/vases/mugs/figurines), no glass or literal "antiques" — used what was actually visible rather than forcing the original 5-category brief.

## 🐛 Bugs Fixed

| Bug | File | Root Cause | Fix Applied |
|-----|------|------------|-------------|
| All 7 Caracas video generations failed instantly | Higgsfield `kling3_0_turbo` calls | Source `frame-N.jpg` images were 325×260px — below the model's usable `start_image` resolution, causing an immediate silent failure (not a slow render failure) | Ran all 7 images through `upscale_image` (bytedance, 2 credits each) to ~2700×2160 before passing as `start_image` |
| `pbakaus/impeccable` skill install kept timing out | `npx skills add` | Repo is ~50MB+; this environment's network is bandwidth-limited (~200-300 KiB/s), not broken | Retried with `SKILLS_CLONE_TIMEOUT_MS=900000` (15 min) — succeeded |
| Public catalog API would have 403'd for anas | `app/core/services.py` `require_service` | `/store/*` and `/catalog/*` public endpoints check *different* service keys ("store" vs "catalog") — seeding only "store" (the `ecommerce` default) isn't enough | Manually seeded `catalog` service key too in `onboard_anas.py` |
