### Localhost Production Readiness — Store: cart/category separation

`a0b901f` — the day's final, most-cited fix. Root-caused via read-only investigation first: rk's
Store page (`CatalogPage.jsx`) only checked tenant-level `canOrder`, never the *currently browsed
category's own* `module_key`, before offering "+ أضف للسلة" — so the real "الخدمات" category
(`module_key: 'catalog'`) got the identical cart affordance as the real "منتجات العناية" category
(`module_key: 'store'`). Adding a service to the cart then broke checkout entirely with a 404 (the
backend's own `store_repo.py` `category.moduleKey == "store"` filter correctly rejecting it —
confirming the backend was always right; the frontend was offering an action it was always going to
refuse). Fixed at the source (`canOrderActiveCategory` gate), not a checkout-side workaround, per
Salman's explicit instruction.

**Also resolved along the way — the long-parked "0 USD" finding**: traced the full real formatting
chain (DB → backend formatter → frontend render) and confirmed, character-by-character, the
displayed digit is `٥` (Arabic-Indic 5), not `0`. Real price is correctly 5 everywhere. Very likely
a misread digit, not a real bug — documented, nothing to fix since nothing is actually broken.

Verified live: rk's Services tab now shows zero add-to-cart UI (DOM-confirmed under hover); rk's
real Store flow completely unaffected including a real cash order through the *normal* checkout
button (deliberately not the WhatsApp button, to isolate what was being tested); mr-h unaffected;
0 console errors. Real test order cancelled afterward.
