### 2. Key Technical Concepts

- FastAPI + Prisma (prisma-client-py) + Supabase Postgres (Frankfurt, `aws-0-eu-central-1.pooler.supabase.com`) + React/Vite on Railway; `gunicorn -w 2`; `TZ=Asia/Beirut` on the container.
- `is_authorized(user, permission, *legacy_roles)` — the single authorization predicate; **invariant I1**: an account with `permissions IS NULL` is judged against **that route's own role tuple**.
- `require_service(key)` reads `client_services`; `platform_services` has zero runtime reads.
- **`OperationDefinition(name, permission, legacy_roles, service_key, write_fn, mirrors_route)`** — frozen dataclass, validated at import; `get()` returns `None` meaning ASK, never a default; **no `lia` permission exists** (invariant I-7).
- **D9 order:** `C → ① Lia access → [operation known] → A operation capability → B permission`, re-run before the write with the SAME definition.
- Three separate gates: ① `lia OR reservations` · ② `OP.service_key` · ③ `reservations` for the escape hatch.
- `moduleKey` on `CatalogCategory` is a **partition discriminator**, not a capability gate; the VALUE `"catalog"` names both a partition and a capability key.
- `CatalogItem` (buy side) vs `CatalogService` (book side) — opposite relation graphs, must not merge.
- **Timezone convention (proved by construction):** the platform stores **local wall clock wearing a UTC label**. `_check_working_hours` reads the RAW value's `%H:%M` against the shop's local hours, and 52/52 production rows fall inside 09:00–21:00 — impossible for a true UTC instant. ⇒ **DO NOT CONVERT.**
- **INVARIANT vs TRANSITION** test assertions (opposite lifetimes).
- **A fake poorer than reality produces a false negative**; always read exit codes, never `$?` after a pipe.
- `ast.unparse` with docstrings stripped — the only correct way to assert "this source never calls X".
- Patterns named by the user: Human-in-the-Loop, multi-turn slot filling, RAG-lite grounding.
