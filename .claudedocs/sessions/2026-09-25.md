### 2. Key Technical Concepts

- **Lia pipeline:** `_entry_family` → `_resolve_actor` → C→①→A→B authorization → model extraction → `_advance` → preview → ✅ → `_commit` / `_still_authorised` → service-layer write. Operations registry in `app/services/lia_operations.py`.
- **Server enforces invariants, not the model:** max 15 per batch before any write; anti-invention (an amount must appear as a number in the owner's own text); deterministic duplicate detection in code — **the model never sees DB rows**.
- **Structural (not flag-based) double-write guard:** recorded `(مسجّل)` lines never enter `draft["items"]`, and `_commit_daily_log` writes only draft items.
- **The invariant:** every draft mutation returns to the same detector (`_duplicate_group` inside `_advance_daily_log`); no side path to the preview or to a write.
- **Arabic folding** `_fold_ar` for name matching; `_within_one_edit` for one-character misses.
- **`metadata.daily_log{v:1}`** = `{v, amount, currency, service_said}` + optional `same_person`; a temporary bridge (Finding 14); `arrived_at` lives in the draft only.
- **Reads:** `ReservationRepository.list_by_client(client_id, None, "arrived", day0, day0+1, 500, barber_id)` — tenant isolation in the `where` clause; `reservation_service.list_reservations` can't be used for daily-log identity because `_fmt` omits `source`.
- **PostgreSQL READ COMMITTED**: each SELECT sees its own snapshot ⇒ "read once and keep" is invalid; detection happens at preview only, and the window before ✅ is a documented contract limit.
- **Sealed production reader:** `scripts/lia_live_evidence.py` seals 275 prisma write methods and proves the seal with a real attempt before any read.
- **Test discipline:** TRANSITION notes naming every old value; AST checks instead of text greps; a fake must not be kinder than reality.
- **Deployment:** `railway status --json` (commitHash), `railway logs --json`; startup must show `Application startup complete` for both gunicorn workers (a missing prompt key fails startup).
