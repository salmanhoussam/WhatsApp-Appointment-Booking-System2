# Track A (Calendar) — Phase A3.1: Day View Resource Columns — Evidence (2026-08-22)

Implements Day's own recommendation from the reviewed and approved UX study
(`.claudedocs/work/calendar-uxui-study/2026-08-22/summary.md`, direction **D1**), refined by
Salman's 5-point follow-up review of the design proposal artifact. Scope, per his explicit
instruction: implement per the approved design, preserve every existing popover/create/reschedule/
drag-and-drop mechanism, no new redesign.

## Change

Two files, additive/rewiring only — no backend, no schema, no DB change:

- **`ReservationsTab.jsx`** — `visibleBarberId` (single) → `visibleBarberIds` (array). Default
  selection effect moved up from `ReservationsTodayView.jsx` (which fully remounts on every
  `load()`) and changed from "first barber" to "every active barber" — a one-time `useRef` guard
  (`barberSelectionInitRef`), not array-emptiness, since an empty selection is now a real,
  legitimate state a user can reach deliberately (deselecting every chip) and must not be silently
  reset. `toggleVisibleBarber`/`selectAllBarbers` handlers added. STAFF (`myBarberId`) unaffected —
  still seeds and locks to exactly their own barber, never auto-defaulted.
- **`ReservationsTodayView.jsx`**:
  - `StaffColumn` renders once per visible barber instead of once total. Its own real hours
    (`barber.working_hours`, A2.2's resolution) hatch the portion of the SHARED grid range outside
    them — the shared range is the union (widest open→close) across every visible barber, so no
    one's real hours are ever clipped by the gutter, while each column still visually shows exactly
    where its own barber is closed.
  - The single cross-column "الآن" (now) line moved from per-column to once, spanning every
    column — correct now that every column shares one real time axis (previously true by
    coincidence, since there was only ever one column).
  - `handleEmptySlotClick` refuses a click inside a barber's own closed-hours region (hatched area)
    instead of opening a Create popover the backend would just 409 on — same "never offer what the
    backend would reject" guarantee A2.2 established, now applied per column.
  - `handleDragEnd` now reads `over.id` (the target column's droppable id = `barber.id`, the same
    mechanism `ReservationsWeekCalendar.jsx` already proves correct for its own day-columns) and
    includes `barber_id` in the reschedule payload only when it changed — enabling drag-to-reassign
    between barber columns. This is **not new backend work**: `reservation_service.edit_reservation()`
    already fully supports `new_barber_id` (checks the target barber's own hours/conflicts, and
    already blocks a STAFF caller from reassigning away from themselves — confirmed by reading
    `app/services/reservation_service.py` lines 459-538 and `app/api/v1/admin/reservations.py`'s
    `RescheduleIn`/`EditReservationIn` schemas directly before writing this), and Week's own drag
    already exercises the identical path. A3.1 only wires an existing, already-secured capability
    into Day now that it has real columns to drop between.
  - Barber picker: single-select pills → multi-select chips + an "الكل" shortcut (fills every
    barber; its own active state is just "does the current selection already equal all barbers").
  - Two distinct empty states: `barbers.length === 0` ("لا يوجد موظفون نشطون") vs.
    `visibleBarbers.length === 0` ("اختر حلاقاً واحداً على الأقل لعرض الجدول") — the second is real
    now that selection is a set the user can empty on purpose.
  - Quick Create header button now defaults to `visibleBarbers[0]?.id` (was the single
    `visibleBarberId`).

## Side Finding — not fixed, not opened for work

One real, reproducible `500 Internal Server Error` on `GET /api/v1/admin/settings?client_slug=rk`
on a fresh page load, self-resolved by an identical retry request immediately succeeding (200).
Intermittent, not deterministic — consistent with this project's previously-documented "unrooted
Supabase pooler flakiness" (see memory: RK/Ali rollout notes; also the root cause behind
`.claudedocs/work/store-investigation/2026-07-21/`'s own earlier finding of the same class).
Pre-existing, unrelated to any file A3.1 touched (`ReservationsTab.jsx`/`ReservationsTodayView.jsx`
never call `/admin/settings`). Registered here per this project's Investigation Protocol, not
silently dropped — not investigated further or fixed, per standing instruction not to open new
parked findings without explicit authorization.
