## §٠ — الهدف

```
من:   Service/Motif يقول المدّة والشروط                     ← P3 ✅
إلى:  Resource + working hours + existing reservations + duration  →  available slots
```

والمسار: `Patient → Service/Motif → Doctor(Resource) → Date → slots`.

**والحجزُ النهائيُّ يستعمل منطقَ التوفّر نفسَه** — لا محرّكٌ للموقع وآخرُ لواتساب لاحقاً.

### التقسيم

```
P4-A  تحقيق        ✅ منجَز (قراءةً فقط)
P4-B  العقد        ← هذه الوثيقة
P4-C  التنفيذ      محرّكٌ مبنيٌّ على المورد، بلا كسر الحلاق
P4-D  الـAPI        نقطةُ توفّرٍ للعيادة
P4-E  أمانُ السباق  تزامنٌ + تفرّدُ DB + فشلٌ حتميّ
P4-F  البوّابة
```

## §١ — العقد: فصلُ **البحث** عن **الحساب**

هذه هي الفكرةُ كلُّها، وهي مُقَرَّةٌ سلفاً في C4.3:

```
البحثُ عن مالك التقويم     يبقى لكلّ جدولٍ على حدة   (Barber / Resource — جدولان، لا يُوحَّدان)
حسابُ الأوقات               يصير واحداً               (ساعات + حجوزاتُ اليوم + مدّة ⇒ slots)
```

**ممنوعٌ `get_clinic_slots` توأماً لـ`get_available_slots`** — هذا تكرارُ خطأ الحلاق حرفيّاً.
**وممنوعٌ توحيدُ `Barber` و`Resource` في جدول** — ذاك تغييرٌ في الحلاقة.

المحرّكُ يأخذ **الحالةَ المحلولة**، لا معرّفَ جدول. الدوالُّ القائمةُ تصير أغلفةً رفيعةً فوقه،
وسلوكُها محفوظٌ بالتعريف — ويُثبَت بـRG-6، لا يُفترَض.

**والتوقيعُ النهائيُّ لا يُثبَّت هنا** (قرارُك في P1). يخرج من التنفيذ، بشرطِ أن يحترم الفصلَ أعلاه.

### السلسلة التي يجب أن ينفّذها العقد

```
Service          →  durationMin  (خادميّاً — ق-٤-أ)
   ↓
eligible Resources  →  ResourceService  (ق-٤-ب)
   ↓
Resource working hours  →  Resource.workingHours  [→ Client.config؟ ق-٤-د]
   ↓
existing reservations   →  استعلامُ يومٍ واحد، status IN (pending, confirmed, arrived)
   ↓
duration + slot step    →  ق-٤-ج
   ↓
valid slots
```

## §٩ — 🔴 بندُ الوقت · مُعلَّقٌ بكلمةٍ واحدة

تصديقُ §٣ فيه شِقّان يتناقضان، والتناقضُ مقيسٌ لا مُستنتَج:

```
①  «الماضي يُستبعَد حسب ساعةِ الحائطِ المحلّيّة»        ⇐ هذا هو السلوكُ القائم
②  «مع UTC-aware صحيح · ولا نسمح بـdatetime.now().replace(tzinfo=utc)»
                                                      ⇐ هذا عكسُه تماماً
```

**والدليل:**

| ما وجدتُه | الموضع |
|---|---|
| الحاويةُ تعمل بـ**`TZ=Asia/Beirut`** ⇒ `datetime.now()` = ساعةُ حائطِ بيروت | `reservation_service.py:450` · `lia_owner_entry.py:1071` · `:3801` |
| `reservedAt` مخزَّنٌ **ساعةَ حائطٍ محلّيّةً بلصاقةِ UTC** في كلِّ المنظومة | `public/reservations.py:68-78` |
| النمطُ الممنوعُ هو **الإصلاحُ نفسُه**، بإيداعِك أنت | `044aafe` (٢٠٢٦-٠٨-٠٥) + `d77ddce` (٣ حرّاسٍ أخرى) |
| والعطلُ الذي أغلقه **مُثبَتٌ بالمتصفّح**: الساعةُ ١٧:٣٧ محلّيّاً والنقطةُ ترجّع أوقاتاً من **١٥:٠٠** | نصُّ `044aafe` |
| النمطُ حيٌّ في **٦ مواضعَ** في مسار الحجز، و**٦ حزمِ فحصٍ** تثبّته | `grep` مقيس |

⇒ تطبيقُ ② حرفيّاً **يعيد فتحَ عطلٍ مغلَقٍ بالمتصفّح**، بفارقِ ٣ ساعات، على الحلاق لا على العيادة.

**وRG-6 يحسمها داخل P4 بنيويّاً:** البوّابةُ تشترط `same input → same Barber output` عنصراً بعنصر.
فمحرّكٌ يحمل تعريفاً آخرَ لـ«الآن» يُفشل RG-6 **بالبناء**. ⇒ داخلَ P4، السطرُ يُحمَل كما هو، وإلّا
فلا P4.

### الخياراتُ الثلاثة

```
(أ) 🟢 توصيتي   P4 يحمل العرفَ حرفيّاً · ومبدأُ ② يُسجَّل ديناً باسمِه (F-TZ-1) لعقدٍ مستقلّ
(ب)            هجرةُ توقيتٍ حقيقيّةٌ الآن: عمودُ timezone للتينانت + تحويلُ ٦٦ صفّاً قائماً
                + ٦ مواضعَ + Lia + الحلاق ⇒ **عقدٌ منفصلٌ بحجم P4، خارج العيادة كلّها**
(ج) 🔴 مرفوضةٌ  UTC حقيقيٌّ للعيادة وحدَها ⇒ قارئُ العيادةِ يخالف كاتبَها (`:460`) بـ٣ ساعات
                — أي نفسُ الانفصامِ الذي أغلقته ق-٤-د قبل سطرين
```

**لا أكتب سطرَ «الآن» في المحرّك قبل كلمتِك على (أ) أو (ب).**
