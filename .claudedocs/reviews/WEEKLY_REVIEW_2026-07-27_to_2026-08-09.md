## Architecture Decisions Made

- Tenant-wide `moduleKey` retired in favor of plural `activeServices` (ratified TOS-004).
- No shared `ReservationStrategy` extraction yet — Clinic/Barber duplication is real but cheap
  (standing rule, 2 named triggers to revisit).
- `CatalogService` is its own real model, not a `requires_booking` flag on `CatalogItem` — the
  Service/Item domain split is now structural.
- 3-tier authorization model (Super Admin / Tenant Owner / Staff) is real infrastructure, not a
  plan.
- `store.py`'s admin Categories/Products endpoints are the correct backend for a dedicated Store
  UI — no new backend needed for Staff/Store IA Separation.
