# Lia P1 — تعديل المسوّدة قبل الحفظ · وصياغة الإلغاء

> **الموافقة (سلمان، ٢٠٢٦-٠٩-١٤):** *«موافقة واضحة على P1 + إصلاح صياغة الإلغاء فقط»*،
> بتسلسل **plan → verification → code**، و**لا push ولا deploy ولا كتابة إنتاج إلا بموافقة
> مستقلّة**.
>
> **ولا يُفتَح في هذه الجولة:** `category` · `product` · الحجوزات · Phase 2 · Item Order ·
> صوت/صورة · أي قالب ميتا · حذف «تنظيف البشرة» أو «خدمة اختبار» (بيانات فحص حقيقية، وحذفها
> كتابة إنتاج لم تُوافَق).

## ١ · المشكلة — مقيسة لا مفترضة

**الحلقة تعمل طرفاً لطرف ومُثبَتة على الإنتاج** (٢٠٢٦-٠٩-١٤ ١٨:٢٢:٣٣ UTC: «تنظيف البشرة»
30 USD · 45 دقيقة · الفئة «الخدمات» · `active=True`، و`public_list_services` تُرجعها للزبون).
فهذه الجولة **تُصلح خللاً في حلقة قائمة**، لا تبني قدرة جديدة.

### أ · نصٌّ في حالة التأكيد لا يُقرأ كتعديل

اليوم، في `LIA_AWAITING_CONFIRM`، أي رسالة نصّية تُجاب بـ«اضغط ✅ ضيفها أو ❌ إلغاء 👆». وميدانياً
(٢٠٢٦-٠٩-١٣ ١٧:٤٣):

```
Lia:    البروتين للشعر | 30 USD | 45 دقيقة   [✅ ضيفها] [❌ إلغاء]
سلمان:  غير اسم الخدمة إلى بروتين
Lia:    👆 اضغط ✅ ضيفها أو ❌ إلغاء            ← أعادت نفسها
سلمان:  عدلها قبل أن تحفظها، غير الاسم من بروتين للشعر إلى بروتين فقط
Lia:    👆 اضغط ✅ ضيفها أو ❌ إلغاء            ← ومرّة تانية
```

فاضطرّ إلى تأكيد اسم لم يُرده، ثمّ تصحيحه من اللوحة.

### ب · الإلغاء كليّ ولا رجعة فيه، ولا يُرشِد

```python
if value == CANCEL_ID:
    _save_draft(session, None)            # ← المسوّدة تُدمَّر
    session.state = "IDLE"
    log_security_event("lia_draft_cancelled")
    send_text("تمام، ألغيت الطلب 👌")       # ← وينتهي هنا
```

وقارنه برسالة انتهاء المهلة في نفس الملفّ، التي **تُرشِد**:

```
انتهاء المهلة:  «مرّ وقت طويل على الطلب فألغيته 🙂 ابعتلي الخدمة من جديد إذا بدك.»
الإلغاء:        «تمام، ألغيت الطلب 👌»
```

### 🔑 والاثنان عطلٌ واحد

**الإلغاء هو اليوم الطريق الوحيد لرفض معاينة، فيُستعمَل كـ«تعديل».** ولهذا يؤلم: حقل واحد خطأ
⇒ إعادة كتابة الجملة كلّها. أصلح التعديل، ويصير الإلغاء نادراً وصادقاً — يعني «لا أريدها»، لا
«أريدها بشكل آخر».

## ٢ · التصميم — قصد `edit_draft`

```
مسوّدة معروضة  (LIA_AWAITING_CONFIRM)
      │
      ├─ ✅ ضيفها      →  يُكتَب   (قائم، بلا تغيير)
      ├─ ❌ إلغاء      →  يُلغى    (قائم، الصياغة تُصلَح)
      └─ نصّ           →  تعليمة تعديل      ← الجديد
                            │
                            ├─ prompt ثانٍ: المسوّدة الحالية + التعليمة
                            ├─ يُرجع الحقول المتغيّرة وحدها (patch)
                            ├─ Pydantic يتحقّق من الـpatch، ثمّ من المسوّدة المدموجة كاملة
                            └─ 🔑 معاينة جديدة + انتظار تأكيد جديد   (إلزاميّ)
```

### القواعد الحاكمة

| # | القاعدة | السبب |
|---|---|---|
| ١ | **إعادة المعاينة إلزامية** بعد كل تعديل، وانتظار تأكيد جديد | المعاينة هي آلية السلامة الوحيدة في الشريحة. تطبيق صامت يُلغيها |
| ٢ | **لا تطبيق صامت أبداً** | المبدأ يبقى: الـAI يقترح · Pydantic يتحقّق · المالك يقرّر |
| ٣ | **الغموض سؤال لا تخمين** | «خليها أحسن» ليست تعديلاً. تُسأل، ولا تُخمَّن |
| ٤ | **المسوّدة القديمة تبقى سليمة عند فشل التعديل** | تعليمة سيّئة لا يجوز أن تُفقِد عملاً صحيحاً |
| ٥ | **لا تعديل بعد الحفظ** | ذاك `update_service` — قصدٌ آخر بعقده الخاص، خارج الجولة |
| ٦ | **الحقول القابلة للتعديل هي حقول `LiaServiceDraft` وحدها** | لا `id` · لا `category_id` · لا `image_url` — نفس استثناءات الشريحة الأولى |

### الـschema الجديد — `app/schemas/lia_drafts.py`

```python
class LiaDraftChanges(BaseModel):   # كل الحقول Optional، وبنفس مُتحقِّقات LiaServiceDraft
    model_config = {"extra": "forbid"}
    name_ar / price / duration_min / currency / name_en / description_ar

class LiaEditPatch(BaseModel):
    model_config = {"extra": "forbid"}
    intent:     Literal["edit_draft"]
    confidence: Literal["high", "medium", "low"]
    changes:    LiaDraftChanges
    unresolved: list[str] = []
```

**ولماذا مُتحقِّقات مكرَّرة لا مُشتركة:** `LiaServiceDraft` حقولها **إلزامية** لأنّ المسوّدة
الكاملة يجب أن تحمل سعراً ومدة؛ والـpatch حقوله **كلّها اختيارية** لأنه يحمل ما تغيّر وحده.
وراثةٌ بينهما تعني إمّا إضعاف الإلزام في الأولى أو تشديده في الثاني — فالمُتحقِّقات نفسها
(`price > 0`، المدة ٥–٤٨٠ من مضاعفات ٥، العملة USD/LBP) تُعاد صراحةً، وهذا مقصود لا تكرار سهو.

**والسلطة تبقى `LiaServiceDraft`:** يُتحقَّق من الـpatch، **ثمّ تُدمَج وتُتحقَّق المسوّدة كاملة
من جديد** عبر `_advance` القائمة — فلا مسار تحقّق ثانٍ يُخترَع.

### القصد لا يُضاف إلى `LiaIntent`

`LiaIntent = Literal["create_service"]` يبقى كما هو. `edit_draft` **ليس قصداً على مستوى
الرسالة** بل عملية داخل مسوّدة قائمة — ولا يُنشئ شيئاً ولا يكتب. خلطهما كان سيسمح لرسالة أولى
بأن تُدّعي `edit_draft` بلا مسوّدة.

## ٣ · التصميم — الصياغة تحت الحكم

> *«الحكم يكون في `app/prompts/lia.md` حتى ما نصنع منطق صياغة منفصل بالكود.»*

كتلتان جديدتان في نفس الملفّ، بسنتينلات كالقائمتين:

```
LIA_PROMPT     (قائمة، لا تُمَس — sha256 778a4462…e93d5e2)
LIA_WELCOME    (قائمة، لا تُمَس)
LIA_EDIT_PROMPT   ← جديدة: prompt التعديل
LIA_REPLIES       ← جديدة: الردود التي تغيّرها هذه الجولة
```

### `LIA_REPLIES` — أربعة مفاتيح، لا أكثر

```
cancel             الإلغاء، ومعه ماذا بعده
confirm_nudge      حين لا تُفهَم الإجابة في حالة التأكيد (وقد تغيّر معناها: النصّ صار تعديلاً)
edit_unclear       الغموض ⇒ سؤال، بمثال ملموس
edit_unavailable   النموذج غير متوفّر أثناء تعديل — والمسوّدة محفوظة، فتُعرَض الخياران العاملان
```

**🔴 ولا تُنقَل بقيّة نصوص الملفّ.** الأربعة هي **ما تغيّره هذه الجولة بالضبط** — والنقل الاستباقي
لبقيّة الرسائل تغييرٌ بنيويّ واسع بلا سبب، وهو ما ترفضه قاعدة التجريد في هذا المشروع. **كل رسالة
تُنقَل حين يلمسها تغيير حقيقي، لا قبله.**

**والتحميل بحرس عند الاستيراد:** غياب الملفّ أو سنتينل أو **أي مفتاح مطلوب** يمنع الإقلاع — نفس
نمط `_load_block` القائم، فالفشل يُمسَك في pre-flight لا عند مالك.

| # | المعيار |
|---|---|
| ١ | `LIA_PROMPT` و`LIA_WELCOME` **مطابقان بايتاً ببايت** بعد إضافة الكتلتين (`sha256 778a4462…`) |
| ٢ | `from app.main import app` ينجح · وحرّاس الكتل الأربع تُطلِق عند العطب |

| ٤ | «غيّر الاسم لبروتين» ⇒ `name_ar` وحده يتغيّر · السعر والمدة **بلا مسّ** |
| ٥ | «خلّي المدة ساعة» ⇒ `duration_min=60` |
| ٦ | «خليها أحسن» ⇒ **سؤال** (`edit_unclear`) · والمسوّدة **كما هي** |
| ٧ | «خلّي السعر صفر» ⇒ يُرفَض بـPydantic · والمسوّدة القديمة **سليمة** |
| ٨ | «خلّي المدة 37 دقيقة» ⇒ يُرفَض (ليست من مضاعفات ٥) · المسوّدة سليمة |

| ١٠ | النموذج غير متوفّر أثناء تعديل ⇒ `edit_unavailable` · **المسوّدة محفوظة** · الزرّان يعملان |
| ١١ | ✅ بعد تعديل ⇒ يُكتَب **بالقيم المعدَّلة** عبر `admin_create_service` |

**ولا نشر ولا كتابة إنتاج إلا بموافقة مستقلّة** — والفحص الحيّ يبقى بيده هو، على رقمه.

## ٦ · ما يبقى خارج الجولة — ومسجَّل

```
🔵 category + product        بعد تثبيت حلقة المسوّدة — والمسارَان مفعَّلان فعلاً
                             (barberlab-test و rk: store ✅ · Category 2-3 · Item 5)
🔵 الحجوزات                  خطّة مستقلّة: runtime transaction لا provisioning
                             (وقت · زبون · ساعات عمل · فحص تعارض)
🔵 update_service            التعديل بعد الحفظ — قصد آخر بعقده
🔵 حذف مسوّدة/خدمة           لا undo، خارج النطاق كما في الشريحة الأولى
🔵 Phase 2 · صوت/صورة · Item Order · قوالب ميتا
🔵 «تنظيف البشرة» و«خدمة اختبار»   تبقى — الحذف كتابة إنتاج غير مُوافَقة
```
