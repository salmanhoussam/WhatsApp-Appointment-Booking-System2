## Findings

### 🔴 R-1 · Reference Validation — cited document is untracked (ORDERING REQUIREMENT)

`app/services/lia_operations.py`, `lia_owner_entry.py` and `capabilities/lia.md` all cite
`.claudedocs/plans/lia-expansion-master-plan.md`, which is **not tracked in git**. Committing the
code first would publish content pointing at a file nobody else can read — the exact violation
closed once before in `3de36bd` / `739647a`.

**This is not a defect in the code; it is a constraint on commit ORDER.** Fix: the plans and the
decision record are committed **before** the code that cites them. Applied in this session's
commit sequence.

### ⚠️ A-1 · Service-layer Prisma calls — an existing deviation extended, not introduced

`rules/backend/architecture.md` §2: Prisma queries belong in `app/repositories/`.

```
app/services/lia_owner_entry.py     at HEAD: 5 direct prisma calls   →  now: 7   (+2)
```

The two added are `_tenant_has_lia` and `_authorise_operation`, both single-table capability
reads, written in the pattern the file already used five times. **The one genuinely new query
shape went to the repository layer where it belongs** (`user_repo.lia_find_active_users_by_phones`).

Stated plainly rather than quietly: extending an existing deviation is still extending it.
Extracting all seven into a repository is a behaviour-preserving `safe-refactor` and is **not**
done here, because this change was scoped to authorization and mixing a layer move into it would
make the diff unreviewable. Recorded as an Open Finding, not closed.

### ✅ F-1 · SEC-01 is a miscalibrated check, not a finding

The audit greps for `startswith.*\$2` as evidence of a plain-text fallback. The matched line is:

```python
# Only bcrypt comparison — no plain-text fallback.
if not hashed_password.startswith("$2"):
    return False
```

That is the guard that **rejects** any non-bcrypt value, fail-closed, next to a comment saying so.
The check matches the fix for the vulnerability it is hunting. Worth recalibrating the command's
pattern; no code change.

### ✅ F-2 · SEC-02's three hits all carry `clientId`

| Flagged line | Reality |
|---|---|
| `clientservice.find_first(where={` ×2 | `"clientId": client_id` is on the **continuation line** — the grep is single-line |
| `user.find_many(where=where, …)` | `where` carries `clientId` when scoped (path A); cross-tenant is **decided behaviour** for path B (D3-c), and ambiguity is refused by count so it can never silently pick a tenant |
